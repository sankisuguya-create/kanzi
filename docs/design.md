# 漢字の森 — 漢字学習サイトの設計

小学生が**自分で予習・復習する**ための漢字学習アプリの設計書。先行研究と根拠は [research.md](research.md)（`S`＝制度・基準、`R`＝研究、`T`＝実装資源）。
設計理念は `-` リポジトリの [サイト設計理念](https://github.com/sankisuguya-create/-/blob/main/principles/site-design-philosophy.md)・[低コスト評価軸](https://github.com/sankisuguya-create/-/blob/main/principles/low-cost-evaluation-axes.md) に従う（以下「原則N」はその番号）。

> **§12 が現在の仕様（全学年版、2026-09）**。§3〜§5・§9〜§11 の「よしゅう」「ふくしゅう」などの記述は3年版のもので、§12 で置き換えた部分がある。

## 1. 目的と範囲

- **目的**: 児童が自分のペースで、授業の前に新出漢字に触れ（予習）、習った字を忘れる前に思い出す（復習）。
- **しないこと**:
  - 他児童との比較（順位・学級平均・他人の進み具合）を児童に見せない。児童画面は本人のデータしか読み込まない。
  - 評価・テストの道具にしない。自己採点を前提にするため、成績に使うと申告がゆがむ。
- **対象漢字**: 学年別漢字配当表 1026字（S2）。読みは当該学年まで、書きは前学年まで＋当該学年を漸次（S1）。

## 2. 決定一覧（WHY）

| # | 決定 | 理由・根拠 |
|---|---|---|
| D1 | 入口は「よしゅう」「ふくしゅう」の2つ。モード（よむ／かく）は児童に選ばせず、スケジューラが決める | 児童の意図（授業前か後か）は機械に分からないので選ばせる。どのカードを出すかは機械が決められる（原則1 自動決定） |
| D2 | 新出字は「提示」から入る：字＋例語＋読み音声＋筆順アニメを同時に見せ、1回なぞる | 刺激ペアリング（R5・R6）。読み先行（R1）。書く練習の反復は求めない（R2・R4） |
| D3 | 読みは「漢字→ひらがなをキーボードで入力→自動採点」。ローマ字は自動でひらがなにし、漢字・カタカナ・英数字は入らない。1回目で正解した時だけ「できた」、まちがいは1回打ち直せ、2回目で答えを見せる。結果のあとは自動で次へ | 想起練習（R7）。利用者の決定（2026-09）で自己採点をやめた。入力はキーボードのみ（3年はローマ字学習の途中なので速さに差が出る点は運用で見る） |
| D4 | 書きは「よむ」が箱3に達した字から出す。対象は前学年まで＋当該学年（学年で打ち切らない） | 読み先行（R1）。旧版の「書きは前学年まで」は S1 の読み違いなので削除 |
| D5 | 書きの採点は字体（画の数・向き・位置関係）だけ。とめ・はね・はらいは採点しない。書き順が違っても不正解にせず、書き終わりに正しい筆順アニメを1回見せる | S4・S5。厳密に判定すると正しい字を誤りにし、自己学習の意欲を削る |
| D6 | 間隔反復は簡易Leitner（箱1〜5、間隔 1/2/4/7/15日）。1日の復習には上限を設け、期限切れが古い順に出す | R10。効果の大きさは保証しない（R8）ので、仕組みは単純な既定値にとどめる。上限がないと長期休み明けに全部の字が一度に来る |

| D9 | 端末に結果をためてまとめて送る。児童1人の進捗は1行にまとめる | GASへの書き込みは1回1〜2秒かかる（原則1 待たせない）。全校を児童×字×モードで行にすると約120万行になり、Sheetsの上限（1000万セル）に迫る |
| D10 | 学年・学級・役割はログインしたメールアドレスと名簿から自動で決める。児童に学年タブは見せない | 原則1 自動決定。児童8桁@kyoiku.edu.nishi.or.jp／教師@edu.nishi.or.jp で役割を判別できる |
| D11 | 書字判定は KanjiVG（T1）ベースの自作（`src/ink.js`）。hanzi-writer の標準データは使わない | T2（中国語の筆順）。自作にしたのは、D5 の「書き順違いを受け付ける」判定が既存ライブラリの1画ずつ判定モードに無いため。精度は §11 |
| D13 | メニューのモードは よしゅう／よむ（入力・自動採点）／かく（タッチペン・自動判定）／カード（かんじ→よみ、よみ→かんじ。入力なし・タップで答え→タップで次。記録しない）。よむ・かくは期限の字がなければ、よしゅう済みの字を練習として出す。かくモードは読みの条件（D4）を待たない | 利用者の決定（2026-09） |
| D12 | メニューには本人の取り組みで育つ森を出す（`docs/forest.md`）。読む・書くの完了で育ち、カードは対象外。最初は36問で1本、27本ごとに次の森。完成ごとに速度は3/4倍。完成森は静止画再利用。「み＝おぼえた字」は出さない。他の児童の量・順位・平均は出さない | 利用者の決定（2026-09-29）。成長量は正誤によって変えない |

## 3. 学習の流れ（カードの状態遷移）

```
未着手 ──よしゅう（D2: 提示＋なぞり1回）──▶ よむ 箱1
よむ 箱n ──おぼえた──▶ 箱min(n+1,5)      よむ 箱n ──まだ──▶ 箱1
よむ 箱3 に初めて達した ──▶ かく 箱0（未習）を追加（D4）
かく 箱0 ──1回の出題で 全画ガイドなぞり → 次の1画だけヒント → ガイドなし──▶ 成功: かく 箱1 ／ 失敗: 箱0のまま
かく 箱n(≥1) ──ガイドなしで字体が合う──▶ 箱min(n+1,5)
かく 箱n(≥1) ──合わない──▶ その場で1画ずつヒントを出して書き直し → 箱1
```

- 次回の日付 = 今日 ＋ 間隔[箱]（1/2/4/7/15日）。かく 箱0 は翌日。
- 間隔は仮の値。学期内の運用を前提に短めにしている（R11 のような最適化はしない）。

## 4. 画面（児童）

### ホーム

```
┌───────────────────┬───────────────────┐
│   （本人の木）     │ [ ふくしゅう 12まい ] │ ← 期限が来たカードの数。0なら「きょうの ふくしゅうは おわり ✓」
│  はっぱ＝やった数   │ [ よしゅう 意育員院飲 ] │ ← 次に出す5字
│  （森: docs/forest.md）│                   │
└───────────────────┴───────────────────┘
```

- 木は Canvas 2D で描く（SVG ではない。表示対象は最大27本、木の画像は画面間で再利用、RGBA換算12MiBまで。詳しくは docs/forest.md「描画負荷」）。前回から増えた分だけ一度弾ませ、常時動くアニメーションは置かない。

- 学年・対象範囲の選択肢は置かない（D10）。
- 予習は1回5字で区切り、終わったら「もう5字 よしゅうする」と「おわる」を出す。続けるかどうかは児童が決める（自分で進める学習なので1日の上限は設けない）。

### ふくしゅう：よむ（最も頻度が高い操作）

```
┌──────────────┐
│   天気        │ ← 例語。対象の字を大きく、ほかは小さめ
└──────────────┘
読みを ひらがなで 書こう   [ ＿＿＿＿ ]い   [ 答える ]
                                        ↑ 送り仮名は入力欄の後ろに出す
[ わからない（答えを 見る）]
答えた後: カードに読み「てんき」を出して自動で1回読み上げ、「次へ」（正解は約1秒・まちがいは約2.6秒で自動で進む）
```

- 1枚の操作 = 想起（学習そのもの）→ ひらがなで入力 →「答える」。採点は機械が行う（児童の自己採点ではない）。まちがえたら1回だけ打ち直せる（2回違うと答えを見せる）。
- 答えは送り仮名をのぞいた部分（悪い → わる）。送り仮名まで書いても正解にする（§12.2 同じ）。

（以前の案: カードを裏返して「まだ／おぼえた」の2択。入力式に変わったので残さない）

### ふくしゅう：かく

- 表面：読み仮名つきの例語（対象の字は□）。下にマス。
- 1画ごとに判定する。書いた画を「まだ書いていない画のどれか」と照合し、どれにも合わない画は薄く消して、その画だけ書き直す。期待した順と違う画に合った場合は受け付けて順序違いとして記録し、書き終わりに筆順アニメを1回見せる（D5）（即時フィードバック、R15は弱い根拠なので即時を選んだ理由は「できたか分からない状態を作らない」＝原則1）。
- 判定の許容幅は広めにとる（R16）。判定エラーが続いたら「おてほんを見る」を出し、筆順アニメへ逃がす。

### よしゅう（提示）

（旧版の設計。§12.2 で よしゅうは廃止。現在の児童メニューは よむ・かく・カード・ぜんぶ見る。参考として残す）

- 字を大きく表示し、筆順アニメを自動で1回再生する。例語を1〜2個、読みは音声つきで出す。
- 薄いガイドの上を1回なぞって「つぎへ」。なぞりは採点しない（D2：反復させない）。

## 5. 画面（教師）

使う度合いは画面ごとに違う（いまの進捗・字別の集計・テスト範囲の一覧は週〜日次で見る。進度・出題順・過年度データなどの設定は学期に数回）。丁寧さを優先してよい。

- **進度設定**（D8・任意）: 採択教科書の単元を選ぶ。予習キューの優先順に効くだけで、児童の進み方は縛らない。
- **字別の集計**: 学級で「よむ 箱1」に残っている児童の割合が高い字の一覧。児童名は出さない（授業で取り上げる字を選ぶための情報）。
- **書き順の提示**: 1〜6字を選び、1字ずつ画面の高さいっぱいに筆順アニメをくり返し再生する（1回終わるごとに1.5秒止める）（左に訓読み、右に音読み。縦書き。読みがなは画面の高さの14%を基本とし、長い読み・複数の読みは余白に収まるよう自動で縮める。音はカタカナ、読みがなは太字。訓の送り仮名は同じ大きさ・太字の青で、語幹との間に短い縦棒を置く（色だけに頼らない）。読みは1文字ずつ縦に積んで描く（CSS の縦書きでは区切りの位置がずれるため）。送り仮名は例語の実際の表記から取る）。クリック・→・Space・Enter で次、← で前、Esc・× で終了。最後の字の次は、選んだ字を字が最も大きくなる行数でならべ、書き順をくり返し再生する（読みは出さない）。読みは例語で使っている音訓だけを出す（辞書の元の形。連濁前）。設定（字を選ぶ画面のチェック。この端末に保存、初期値はオン）で、完成した字をうすい灰色で下に出し、その上を黒の線が書き順どおりになぞる形にできる。始めると全画面になり、Esc 等で抜けても、クリック・キー・右上の「全画面」ボタンでまた全画面に戻る（GAS の埋め込み表示で全画面が許可されない時は、ボタンを全画面キーの案内にする）。字の後ろには外枠の正方形と十字の点線を置く（児童が字全体のバランスをつかむ目安）。ならべる時は字と字の間を画面の短辺の4%空け、点線が隣の字とつながって見えないようにする。字を選ぶ画面は、学年タブと漢字一覧がいちばん上に置かれ、一覧が最初から最上部に見える（学年タブを切り替えても同じ位置に戻る）。選んだ字・チェック・「はじめる」は一覧の下。
- **児童画面のおためし**: 先生画面から児童画面を開いて試せる。上部の帯に「1日すすめる」（翌日以降の出題を確かめる）・「はじめから」・「先生画面にもどる」を置く。記録は端末の別の場所（`kanzi.trial.<メール>`）に保存し、サーバーへは送らない（児童の集計を汚さない）。予習の順は選んでいる組の進度に従う。「まちがいの多い漢字」は その子ではなく学級の集計から出す（3人以上が答え、最後の答えがまちがいの人がいる字を割合の高い順。おためしの記録は空なので、児童本人のまちがいは出せない）。
- 児童ごとの一覧は置かない（§1 比較しない・評価に使わない）。必要になったら担任の判断で追加を検討する（§10）。

## 6. データ

### 漢字データ（静的・リポジトリに同梱）

```
Kanji {
  char, grade(1-6), strokes,
  readings: [{ kana, type: "on"|"kun", stage: "小"|"中"|"高" }],   // S3。小学校で出題するのは stage="小" のみ
  words:    [{ word, kana, readingIndex }],                         // D7。readingIndex は readings の添字
  bushu,
  order:    { <教科書会社>: 新出順の番号 }                            // D8
}
```

- 正本: 学年別漢字配当表（S2）・音訓割り振り表（S3）・採択教科書の新出漢字一覧。筆順は KanjiVG（T1）の SVG を字ごとのファイルにして、表示する時に読み込む。

### 進捗データ（児童1人＝1レコード）

```
Progress {
  userId,
  read:  { <char>: [box, due, reps] },     // due は基準日からの日数
  write: { <char>: [box, due, reps] },     // box 0 = 未習
  previewPos,                               // 教科書順の予習位置
  updatedAt
}
```

- 学習した字だけを持つ（未着手の字は書き込まない）。
- Sheets では1児童1行、`read` と `write` を別々のセルに JSON で置く。1字は最大でも約36文字（`"字":[5,99999,999,1790000000000,999],`）× 1026字 ≈ 3.7万字で、セルの上限5万文字に収まる（不変条件 I6。`tests/scheduler.test.mjs` で1026字すべてを検査）。
- 旧版の Session（学習記録）は持たない。児童画面の「きょう◯まい」は端末内で数える。教師の字別集計は Progress から計算する。

## 7. 保存と同期（Platform層）

- `Platform` 抽象層を挟む（原則4）: 本番＝GAS＋Sheets、デモ＝localStorage。GASにデプロイしなくてもブラウザだけで全部動く。
- 操作の結果はまず端末（localStorage）に書き、画面はすぐ次のカードへ進める（楽観描画、0.1秒以内）。
- 送信は、ひと区切り（5字または10枚）ごとと、画面を離れる時にまとめて1回行う。通信が切れていたら端末にためておき、次に開いた時に送る。
- 複数の端末で使った場合は字ごとに `due` の新しい方を採る（1字単位で統合するので、どちらの学習も失われない）。
- 保存する時、形の違う字エントリは字単位で直す・落としてから統合する（`dropBadEntries_`。5要素でない・箱が範囲外・負の値は落とし、まちがい回数の無い旧形式は0で補う）。壊れた一部のために全部の保存を止めない。
- 設定（出題順・見せる学年・テスト範囲など）の書き込みはスクリプトロックで順番にする（同時に書いた時に古い値で上書きしない）。ロックの中では必ず設定を新しく読む（その実行がロック前に読んだ控えを使い回すと、同じキーの行が二重にできる）。ゲート設定のキャッシュ上書きもロックの中で行う（外に置くと同時保存でキャッシュだけ逆順に残る）。
- 起動時に読み込むのは漢字データ（1〜6年、約140KB）と筆順データ（約670KB。§16）と本人の Progress 1行だけ。

## 9. 実装の順序

1. **基盤**: 漢字データ（配当表・音訓割り振り・教科書順・例語）の整備と I1・I2 の検査 → スケジューラ（§3、I3〜I5 のテスト）→ Platform（localStorage版）。
2. **よしゅう＋ふくしゅう（よむ）**: ホーム、提示（筆順アニメ・音声）、よむカード。ここで localStorage 版のデモが一通り動く。
3. **ふくしゅう（かく）**: KanjiVG を使った1画ごとの判定（T3を評価してから採否を決める）、D5 の採点規則。
4. **GAS版 Platform**: 名簿による自動判別（D10）、まとめて送る同期（§7）。
5. **教師画面**: 進度設定、字別の集計。

- 「かく」を3番目にした理由：予習の提示（筆順アニメ）と よむ はどちらも KanjiVG の表示だけで作れ、判定が要らない。書字判定は最も不確実な部品なので、手順1・2 が動いてから T3 を実機（CZ1104、ペン・指）で評価する。
- 「日本語母語の児童は書きの方が弱い」という見立てが原典で確かめられたら（research.md 末尾）、手順3 を 2 と並行させる。

### 書字判定の方式と測定値

- 書いた線を弧長で32点に取り直し、まだ書いていない各画と点ごとの平均距離で比べる。許容は109四方の座標で19。字全体のずれは、受け付けた画のずれの平均で補正する（上限14）。
- 期待した画に合えば受け付ける。合わなければ残りの画のうち最も近いものに合えば受け付け、書き順違いとして数える。どれにも合わない線は消す。「じぶんで」で同じ画を2回続けて外すと次の画のヒントを出し、その字は不正解（箱0または箱1）になる。
- 向き: 点など短い画（長さ22未満）は問わない。それ以外で逆向きに書いた線は受け付けず「むきが ちがう」と出す。
- 合成データでの測定（`KanjiVG` の線をそのまま・変形して入力）:

| 条件 | 200字中、ヒントなしで書き終えた字 |
|---|---|
| そのまま | 200 |
| 全体を右下へ8ずらす | 200 |
| 0.8倍に縮小 | 200 |
| 各点に±3の手ぶれ | 200 |
| 0.75倍に縮小＋6ずらす | 197（写・深・流が不可） |
| 画数が同じ別の字を書く（3862組） | 字全体を誤って受け付けたのは7組（温↔港、仕↔他、送↔追、集→寒） |

- 児童の実際の筆跡は、字の中の配置が崩れる点で合成データより厳しい。実機での測定が必要（§10）。

## 12. 全学年版（2026-09、利用者の指定による改訂）

### 12.1 範囲と学年
- 1〜6年の1026字すべて（`data-src/words-g1.txt`〜`words-g6.txt`、例語2001語）。例語の他の字はその学年までの配当漢字に限る（生成時に検査）。

### 12.2 児童のメニュー
- 木／漢字を ぜんぶ見る／よむ／かく／カード（かんじ→よみ、よみ→かんじ）／えらんだ漢字を見る。よしゅうは廃止。
- **漢字を ぜんぶ見る**: 「見る」「えらぶ」を切り替える。見る＝右に提示画面と同じ表示（外枠・十字・うす文字の上を黒で書き順をくり返し・左右にふりがな）、左に例語（読み上げつき）。えらぶ＝押した字を「えらんだ漢字」に入れる／外す。
- **出す字の選び方**（よむ・かく・カード共通）: おすすめ（間隔反復の期限が来た字。1日の上限つき）／えらんだ漢字（最大30字）／ならった漢字から ランダム／まちがいの多い漢字（まちがい回数÷答えた回数が高い順）。1回の問題数は よむ・カード10、かく5。
- **よむ**: 答えは送り仮名をのぞいた部分（悪い → わる）。入力欄の後ろに送り仮名を青で出す。送り仮名まで入力しても正解にする。
- **かく**: 見本・なぞりなし。同じ線を2回続けてまちがえたら、ヒントは出さずに正しい書き順アニメを見せて「まちがい」で次へ（利用者の決定）。
- **カード**: 画面のどこを押しても 答え → 次。記録しない。
- **おわり**: 最後まで終えた時だけ木が育つ（その回の問題数ぶん）。出た字の一覧に○×を出し、チェックを外すと えらんだ漢字から外れる。

### 12.3 データ（進捗）
- 1件 = `[箱, 期限, 回数, 最後の時刻, まちがい回数]`。
- `sel`（えらんだ漢字）＝ `{字: [1|0, 時刻]}`、`done`（最後まで終えた回）＝ `{開始時刻: 問題数}`。端末間では、選択は時刻の新しい方、終えた回は和集合で統合する。
- スプレッドシートの「進捗」は `メール, read, write, meta(sel・done), 更新` の5列。

### 12.4 リスク
- `gas/Index.html` は全学年の筆順データを含めて約1MB。GAS の HtmlService で問題なく開けるかは実環境で未確認。重ければ学年ごとの筆順データを必要な時に読み込む方式に変える。

## 25. ぶんの ぶんかい（2026-10、利用者の指定による追加）

- **目的**（利用者）: 教科書の「文の成分」の学習を、提示された文を 主語・述語・修飾語・接続語・独立語 の5役割に分け、修飾語は係り先の文節も選ぶ活動として実装する。児童画面の右下の「その他」ボタンから入る（「その他」は今後の活動の入口を並べる chooser 型の画面）。
- **画面の流れ**: メニュー →「その他」→「ぶんの ぶんかい」で 50問＋学級の自作問題を通しで解く。1問ごとに2段の判定: **語の役割を全部答える → 正誤判定 → 修飾語のつながりを全部答える → 正誤判定**（利用者の指定）。各段で、1回目の失敗は まちがいだけ消して正解は残す（ロック）、2回目の失敗か「わからない」は答えを出して次の段へ進む。「わからない」の問題は成長の対象に数えない（よむ・かくと同じ約束）。
- **操作**: 文節チップをおして役割パレット（主語・述語・修飾語・接続語・独立語。漢字メインに読み仮名のルビつき — 利用者の指定）で当てるか、役割チップを文節へドラッグしてはなす。係り先の段では 修飾語チップをおして係り先の文節をおすか、修飾語チップから係り先へドラッグする（タップとドラッグの両対応）。係り線は教科書と同じ下ブラケット＋矢じり（文節の下に くの字、係り先の文節に矢じり。同じ係り先への線は共通レーン、短い線ほど浅いレーン、行をまたぐ線は出し手の行の下を通る）。
- **役割の見せ方**: 色でなく語バッジ（`主語/しゅご`の小さなバッジ）で示す。5役割は色分けの上限（同時に4色まで・color-coding）を超えるため色は使わない。選択中は青い枠・係り先モード中は係り先候補が点線になる（形と色の二重の手がかり）。
- **問題集（内蔵50問）**: `data-src/bunkai.txt` が正本（`id 文節=役割[>係り先番号] …`）。`npm run build:bunkai` で `src/bunkai-data.js` を生成。生成時に機械検査する: 文節2〜8・述語ちょうど1・主語高々1・修飾語は係り先番号が要る・係り先は 主語/述語/修飾語 のみ・自分自身は不可・文節の漢字は {字|よみ} の中にだけ書け3年配当まで（未習字はひらがな。利用者の指定）。文そのものは自作（インターネットの問題を そのまま移さない。文法面は教科書の係り受けの考え方に合わせて確認した）。
- **先生が自分の文を追加できる**（利用者の指定）: 先生画面「ぶんかい」区画の「問題を つくる」で、文を空白で文節に分けて書き、児童と同じ画面で役割と係り先を当てて登録（当てた内容がそのまま答えになる。解ける形か その場で分かる）。保存はゲートと同じ学級キー方式（設定シート `bunkai:<学級>` にJSON、CacheService 10分、先生が保存したらすぐ上書き → 児童には最長30秒ほど）。形の検査は `Sched.normBunkai`（児童・先生・GAS で共用の唯一の実装）。自作は内蔵の後ろに並び、最大50問。一覧から消せる。
- **記録**: 進捗の meta に `bunkai: { 問題id: [答えた回数, まちがい回数, 最後に答えた時刻, 最後にまちがえた時刻, 役割まちがい累計, 係り先まちがい累計] }`。統合は「最後に答えた時刻」の新しい方（字の記録と同じ約束）。終えた回は done/old に よむ・かくと同じ仕組みで数える（「わからない」分を除く）。
- **森**: ぶんかいの終了はモード 'b' で記録され、葉は **カードと同じ茶色** で育つ（利用者の指定。森の保存データは4色のまま、'b' はログに 'k' として落とす。モードは modes{} に残るので ぶんかいの回数は区別できる）。凡例の「葉の色」に ぶんかい（茶色・三角）を追加し、注意書きを「よむ・かく・ぶんかいで 育つよ」に変えた。
- **先生画面の分析**（利用者の指定）: 「ぶんかい」区画に、答えた人数・いま最後の答えがまちがいの児童の数（割合）・役割まちがい/係り先まちがいの累計を問題ごとにまちがいの多い順で出す（上位10。児童名は出さない — 学級の字の集計と同じ約束）。
- **ゲート**: `m.other`（その他ボタン）と `o.bunkai`（その他画面の ぶんかいボタン）をゲートの対象に足した（おためしのチップでも切り替えられる）。
- **検査**: `tests/bunkai.test.mjs`（問題集の形・漢字の学年・記録・統合・森モード・normBunkai）、`tests/gas.test.mjs`（自作問題の保存と配信・集計）、e2e。
