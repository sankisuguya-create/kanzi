# 27. 説明文の分解（はじめ・中・おわり）（2026-10、利用者の指定による追加）

設計書 [design.md](../design.md) §27 から分けた機能別の仕様（節番号は design.md と同じ）。全体の決定（§1・§2・§13・§23・§24）は design.md が正本。

- **目的**（利用者）: 6〜7段落の説明文を はじめ・中・おわり に分ける。①段落番号を打つ ②中の始まりと終わり（切れ目）を指定する ③はじめの問い・考え、中の答え・わけ、まとめの文を見つける。「その他」に ぶんかい と並べて置く。
- **対象は3年**（利用者の決定）: 漢字は3年配当までそのまま、4年以上・配当外は {字|よみ}。型の名前（頭括など）は子どもに見せず、先生画面の集計にだけ出す。③の発問は型ごとに変えて、型を明かす（利用者の決定。5・6年向けの「先に型を選ばせる」段は作らない）。
- **本文20本**（自作。教科書の文はうつさない）: 問い・答え型7／話題提示・尾括型5／双括型5／頭括型3。難しさ A（「まず」「このように」などの合図あり）8・B（合図なし）8・C（まぎらわしい: 中に「このように」がある、答えの文が段落の先頭にない、おわりに問いや別の「このように」がある）4。並びは易→難。はじめ1〜2段落・おわり1〜2段落とばらつかせ、位置だけで当てられないようにする。全部 はじめ・中・おわり の3部（頭括型の おわりは 主張をくり返さない付け足し）。確認用の一覧: [setsumei-review.md](../reports/setsumei-review.md)。
- **正本と検査**: `data-src/setsumei.txt` → `npm run build:setsumei`（`tools/build-setsumei.mjs`）→ `src/setsumei-data.js`。検査: 段落6〜7・切れ目で3部に分かれる・a は はじめ・b は中の段落ごとに1つ・c の置き場が型と合う（問い・尾括=おわり、頭括=はじめ、双括=両方。頭括・双括は a の文が c に入る）・a・b の種類が型と合う・漢字の学年・行数が画面に収まる。
- **答えが1つに決まらない所**: b は段落ごとに別解（`4.1/4.2`）、c は「どちらか（両方でもよい）」のまとまり（`6.1/6.2`。「このように〜」とその後の考えの文のように、どちらも まとめと読める時）を持てる。照合は `Setsumei.matchGroups`。
- **行はこちらで組む**（`src/setsumei.js` の `layout`）: 縦書き・1行20字（一字下げを含む）、句読点・閉じかっこは前の行にぶら下げ、{字|よみ} は行をまたがない。段落番号を「行の頭」に打たせるため（どの行が段落の始まりかが確定する）。1366×768 でスクロールなしの上限を30行とし、検査で守る（いまの20本は14〜20行・226〜323字。教科書の説明文よりずっと短い）。
- **未確認**: 本文の事実は図鑑で ふつうに書かれていることに限ったが、先生の目での確認が前提。
- **画面の流れ**（2026-10 実装）: メニュー →「その他」→「説明文の分解」。**1回1文章**（利用者の指定。`Sched.setsumeiPick`: まだ答えていない文章を易→難の順に、全部答えたら最後に答えた時刻の古い順）。発問は1つずつ出す: ①番号 → ②切れ目 → ③a はじめ → ③b 中の段落ごと → ③c いちばん つたえたい こと。各段は「こたえあわせ」で判定し、1回目の失敗は まちがいだけ消して正解を残す（押しなおせない）、2回目の失敗か「わからない」で答えを出し「つぎへ」で進む（ぶんかいと同じ約束）。正解は「✓ せいかい！」のあと自動で次の段へ。
  - **①**: 行（縦の列）を押すと、行の上に番号。押した順に1, 2, 3…、もう一度押すと消える。消して空いた番号があれば、次に押した行には いちばん小さい空き番号が入る（番号を詰めなおすと、すでに打った番号が動いてしまうため）。正解は「番号のついた行＝段落の始まり、かつ 段落の順の番号」。①の間は段落のあいだに すきまを出さない（見た目で段落が分からないように）。
  - **②**: 段落のあいだが押せる幅（34px・点線）になり、押すと太線＋✂。2つまで（3つ目は「消したい切れ目を もう一度」）。2つ選ぶと はじめ（青の地）・中（地なし）・おわり（だいだいの地）と語のラベルが段落の下に出る（色だけに頼らない）。
  - **③**: 文のどこを押しても その文全体に傍線（右の太線・太字）。a は はじめの中から1つ（ほかを押すと「はじめの中から」）、b は中の段落ごとに1つ（同じ段落を押すと入れかえ）、c は どこでも いくつでも。発問は型ごとの言い方（この節の上の決定。型の名前は出さない）。
- **記録**: 進捗の meta に `setsumei: { 文章id: [答えた回数, まちがい回数, 最後に答えた時刻, 最後にまちがえた時刻, ①まちがい累計, ②まちがい累計, ③まちがい累計] }`（どこかの段で1回でも まちがい・わからない なら その回はまちがい）。統合は「最後に答えた時刻」の新しい方。
- **森**: 1文章を終えると 3問ぶん（3段）として数え、葉は ぶんかいと同じ茶色（モード 'b'）。「わからない」を押した文章は数えない。
- **先生画面**: 「説明文の分解」区画に、文章ごとの 答えた人数・いま最後の答えがまちがいの人数（割合）・①②③のまちがい累計を まちがいの多い順で表にする（型・難しさは先生にだけ見せる。児童名は出さない）。
- **ゲート**: `o.setsumei`（その他画面のボタン）。①を省略するゲートは作っていない（ボタン以外のゲートは まだ仕組みがないため。要望があれば足す）。
- **検査**: `tests/setsumei.test.mjs`（本文の形・配分・行の組み方・照合・記録と統合・選び方・森）、`npm run e2e:setsumei`（1366×630 でスクロールなし・①のまちがい→直す・②の色とラベル・③a〜c・わからない・おわり・先生の集計）。
- **名前**（2026-10、利用者の指定）: 児童・先生画面の名前を「説明文の分解」に（§25 の ぶんの ぶんかい は「一文の分解」に）。内部のキー（`setsumei`・`bunkai`・`o.setsumei`・`o.bunkai`）と記録は変えない（既存の進捗・ゲート設定をそのまま使うため）。
- **本文の見直し**（2026-10）: 読みが割れる所に別解を足した（s02 の くふう と その効果、s08 の問いの文、s15・s20 の わけ、s17 の考えの2文）。はじめ/中 の切れ目が割れる s13 の2段落めを 話題の導入に変えた。事実・言い切りを直した（おかきの作り方、朝ごはんと ねむけ、図書館とインターネットの比べ方、車いすのマーク＝体の不自由な人も使える場所、税金は町に おさめられたもの、「あらわれます」→「あらいます」）。
