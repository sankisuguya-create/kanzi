# 成長する森

最新の学習ルールを維持する。読む・書く・カードを最後まで終えると、その回の問題数ぶん育つ。途中で戻った回・一覧を見るだけ・選択するだけでは育たない。正誤で成長量を変えない。ひらがな・カタカナの「書く」も対象。

## 見た目と操作

- 0問は種、1問は新芽、2〜3問は苗木。その後は枝葉が増える。
- 36問で1本が完成し、次の学習から隣に新芽が増える。ケヤキ・サクラ・カエデ・シラカバ・スギを順に育てる。スギは葉の段を連続面でつなぎ、横方向の隙間を抑える。
- 樹冠が重なる密度で植え、木が増えるとカメラが引く。36本で次の森へ進む。過去の森も前後のボタンで見られる。
- 「育てている場所へ」は現在の木だけを表示。「森全体へ」でその木のある森に戻る。
- 読む＝青、書く＝橙、カード（漢字→読み）＝紫、カード（読み→漢字）＝黄。モード不明の既存記録は緑。色の説明は折りたたみ。色は装飾であり、学習や操作の判断に必要な情報は文字でも示す。
- モードを変えなくても全種類の木が育つ。放置による枯れ・減点・他児童との比較はない。

## 記録と移行

既存の `done`（完了回と問題数）、`old`（過去の完了回の合計）が成長量の正本。`forest.modes` に完了回のモードを保存し、月次の `compact` 時に古い回の色を `forest.base` に1問1文字で移す。表示時は過去の色と最近の完了回を開始時刻順につなぐ。同じ回の再送を重複加算しない。旧データに学習モードの記録がない部分は推測せず緑で補う。

`進捗` シートの A〜E 列（メール・read・write・meta・更新）は維持し、F列以降に森のJSONを4万文字ずつ分割保存する。必要な列は保存時に自動で増やす。既存の名簿・教師・設定を作り直す必要はない。先生の集計は既存の列だけを読む。新旧クライアントの混在でも学習量の集計は既存仕様に従うが、旧クライアントで学習した分のモードは復元できない。

成長本数の固定上限は置かない。保存先の容量や通信量には実際の上限があるため、数学的な無限を保証するものではない。10万問の保存・再読み込みと描画を自動検証する。

## 描画負荷

Canvas 2D。表示対象は最大36本、単独表示は1本。縮小時は細かな葉を省略し、完成木の画像を画面間で再利用する。共有画像キャッシュはRGBA換算12MiBまで、描画倍率は最大1.5。背景も再利用する。

成長・カメラ移動は約850ms、最大30fps。静止時は再描画しない。非表示・画面外・画面遷移時は描画を停止し、画面破棄時にイベントと監視を解除する。動きを減らす設定では演出を省略する。計測値は開発用Windows/Edgeのもので、児童用Chromebookの実機計測ではない。

## 検証と反映

`node --test tests/*.test.mjs`、`node tests/e2e.mjs`、`node tests/forest-e2e.mjs`。ブラウザ試験は `playwright-core` と `CHROMIUM` が必要。森の試験は種・新芽・5樹種・色・再読み込み・次の木・10万問・単独表示・描画停止・狭い画面・GAS生成物を確認する。

`node tools/build-gas.mjs` でGAS生成物を更新する。学校への反映は既存のGASプロジェクトのコードを更新し、ウェブアプリのデプロイを更新する。リポジトリの変更だけでは既存のGAS公開画面は切り替わらない。
