# 説明文を書く — 要件定義（2026-11）

> **状態**: 1回目を実装（仕様は [features/setsumei-writing.md](../features/setsumei-writing.md)）。W2 の修正案（R12）は2回目。下の未決 U1〜U5 は決定済み（表の右端）。

3年国語「書くこと」：「すがたをかえる大豆」を読んだ後、自分で選んだ食品について説明する文章を書く単元で使う。
学習指導要領 B(1)イ（内容のまとまりで段落をつくり、段落の関係に注意して文章の構成を考える）。
完成形の基準は、教科書に載っている作例「いろいろなすがたになる米」（はじめ1段落・中3段落・終わり1段落。「まず／次に／さらに／このように」で段落を始めている）。

design.md §28。仕様は実装した時に `features/setsumei-writing.md` に書き、この文書は頼まれた内容の記録として残す。

## 0. 利用者の要件（原文の要約）

1. 縦書き
2. 題がない・名前がない・段落の最初を1字下げていない、を指摘する
3. 題・はじめ・終わりはテンプレートの穴埋め
4. テンプレートのない白紙も選べる
5. 先生が許可すれば、ほかの児童の文を読める
6. 先生の画面で一覧できる。修正も、吹き出しのコメントもできる

## 1. 決まったこと

| # | 決定 | 理由 |
|---|---|---|
| W1 | 漢字の森の新しいモードにする。「その他」の「説明文の分解」（§27）の隣 | 認証・名簿・担当学級（§13）・ボタンのオン・オフ（§23）・過年度（§24）・縦書き20字の組版（`src/setsumei.js`）をそのまま使える。児童の入口が増えない |
| W2 | 先生の修正は**修正案を重ねる**方式。赤字で重ね、児童が採用する | 児童が書いた文と先生の手が入った所を区別でき、評価の資料にも使える |
| W3 | 要件5は §1「児童画面は本人のデータしか読み込まない」の**このモードだけの例外**にする。本文は読むだけ。先生のコメント・指摘の件数・文字数は見せない | §1 の目的（比較させない）を守り、そのうえで読み合いをできるようにする |
| W4 | 1字下げは自動で入れない。指摘だけをする | 自分で1字下げをすることが学習の中身だから（サイト設計理念「思考が目的の画面では判断を奪わない」） |
| W5 | 本文は「進捗」とは別のシートに保存する（1人×1作品＝1行） | 進捗は児童1人＝1行（D9）。児童の保存と先生の修正案・コメントが同じ行に書き込むと、後から書いた方が上書きしてしまう |
| W6 | 児童と先生の判別は、いまの仕組み（`getActiveUser`・名簿・教師シート）を使う | 学校で動いている実績がある（児童と先生でドメインが違っても取れている） |

## 2. 児童：書く画面

- **R1 縦書き**: `writing-mode: vertical-rl`。原稿用紙のマス目を出す（1行20字。マス目が無いと1字下げが見えない）。行の組み方は `src/setsumei.js` の `layout` に合わせる（句読点・閉じかっこのぶら下げ）。
- **R2 全角にそろえる**: 半角の英数字・半角スペースは全角に直す（マス目がずれないように。1字下げを半角スペースで入れても判定できるように）。
- **R3 型を選ぶ**: はじめに「テンプレート／白紙」を選ぶ。あとから切り替えても本文は消えない。
- **R4 テンプレート（穴埋め）**:
  - 題：「すがたをかえる【食材】」（2026-11 利用者の指定で、穴は【食材】だけに。はじめ・おわりも同じ）
  - 名前：自動で入る（直せる）
  - はじめ：「【食品】には、いろいろな【　　】のくふうがあります。」
  - 中：段落の枠だけ（教科書の指導書にある「段落の枠を設けたワークシート」）。
  - 終わり：「このように、【食品】は、【　　】いろいろなすがたになって食べられているのです。」
  - 同じ言葉の穴（【食品】）は、一度入れたら他の場所にも入る。
- **R5 白紙**: 1行目＝題、2行目＝名前、3行目から本文として読み取る。
- **R6 自動保存**: 打つたびに端末に保存し、数秒ごとにまとめてサーバーへ送る（D9 と同じ考え方）。通信が切れても消えない。保存できたかを画面に出す。
- 入力は キーボード（ローマ字）と ChromeOS の手書き入力の両方を前提に、入力欄を大きくとる。3年はローマ字を習っている途中で、打つ速さが書ける量の上限になる。

## 3. 指摘（要件2）

「見なおす」ボタンを押した時だけ出す（書いている途中に出し続けると手が止まるため。根拠は設計上の推測で、実証は無い）。指摘はその場所の横に、記号と短い言葉で出す（色だけで伝えない）。直れば消える。

| 判定 | テンプレート | 白紙 |
|---|---|---|
| 題がない | 題の欄が空 | 1行目が空、または1行目が1字下げで始まる（本文から書き始めたとみなす） |
| 名前がない | 名前の欄が空 | 2行目が空、または名前らしくない（字数・句点から推定する。推定なので「たしかめよう」と言う） |
| 1字下げがない | 段落の始まりが全角スペースでない | 3行目からの段落の始まり |
| 穴が空いている | 【】が空のまま | 該当なし |

句読点・漢字・主語と述語の対応は判定しない（誤検出が多い。先生が見る）。

## 4. 読み合う（要件5）

- **R9**: 先生が学級ごとに「読み合う」をオンにした間だけ、児童の画面に「友だちの文」が出る。オフにすると消える。開いたままの画面にも届ける（§23 と同じ。メニューに戻った時・30秒ごと）。
- **R10**: 読むだけで、直せない。W3 のとおり、本文以外は見せない。

## 5. 先生の画面（要件6）

- **R11 一覧**: 学級の全員をカードで並べる（番号・名前・字数・段落の数・指摘の件数・最後に保存した日時）。書き始めていない児童を上に並べ替えられる。
- **R12 修正案**: W2。先生が文字を選んで直すと、児童の画面に赤字で重なり、児童が「なおす」で採用する。採用前の文も残す。
- **R13 吹き出し**: 本文の横に吹き出しでコメントを付ける。児童の画面にも出し、児童が「よんだ」を押すと閉じる。
- **R14 印刷**: 縦書きA4で書き出す（掲示・評価の資料に）。

## 6. 守ること

- サイト設計理念（`-` リポジトリ）と、漢字の森の既存の決まり（フォント §14・ゲート §23・過年度 §24・版ずれの検知）に従う。
- 4GB・LTE の端末でも打つ文字が遅れない（1文字ごとに全体を描き直さない）。
- 作品のシートは、過年度の「メール・名前をまとめて消す」（§24）の対象に入れる。本文に児童が自分の名前を書いているので、本文の名前の行も消す対象になる（本文に書かれた名前は自動では見分けきれないので、消す時の画面にそう書く）。
- デモ（`index.html`、この端末に保存）でも動くようにする（原則4）。
